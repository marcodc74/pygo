# Pygo — README for AI agents

Pygo is a small, statically typed language with its own bytecode VM, built so
that **code written by a model can be checked and run without supervision**.
It is not Python: there is one way to write each thing, every failure is typed,
and the outside world is reachable only through declared, grantable effects.

If you are an LLM writing Pygo, this page is the contract. The full reference is
[`docs/GUIDE.md`](docs/GUIDE.md) and [`internal/guide/guide.md`](internal/guide/guide.md);
a project template for repos that *write* Pygo is
[`integrations/AGENTS.md`](integrations/AGENTS.md).

## The loop

```
understand task
  -> query the toolchain        pygo guide --stdlib | pygo describe | pygo outline
  -> write or edit code         pygo edit --expect-hash
  -> check                      pygo check --json
  -> fix                        pygo fix --json
  -> test                       pygo test --json <dir>
  -> run                        pygo run --json --allow ...
```

Never `run` unverified code, and never edit by line number: use symbol keys.

## Ground rules

1. **Query, don't memorize.** APIs, types and effects come from the toolchain,
   not from training data. Run `pygo guide --stdlib`, `pygo describe <module>`,
   `pygo outline <file>`, and `pygo explain CODE`.
2. **One canonical form.** `pygo fmt -w file.pg` before finishing; `pygo fmt --check`
   fails if it is not canonical.
3. **Fallible work is typed.** A function that can fail returns `!T`; call it
   with `try expr` or handle it with `expr catch e { ... }`. The checker forces
   the choice (E0401).
4. **Declare effects, least privilege.** A function that touches the world says
   so: `uses fs, net`. The runner grants them with `--allow`. Never grant more
   than the task needs, and never `--allow python` on untrusted code.
5. **Test next to the code** with `test "..." { assert ... }`.
6. **Everything is machine-readable.** Every subcommand takes `--json`.

## Commands

| Command | What it does |
|---|---|
| `pygo check --json file.pg` | Static diagnostics with stable `code`, `hint`, `fix` |
| `pygo fix [--all] [--json] file.pg` | Apply safe fixes (in place) |
| `pygo test --json file.pg \| dir` | Run `test` blocks; failed asserts report operand values |
| `pygo run --json file.pg [-- args]` | Execute (`--engine vm` default, `--engine tree`) |
| `pygo guide --stdlib` | Compact language reference + every stdlib signature |
| `pygo describe file.pg \| module` | API of a file or stdlib module, as JSON |
| `pygo outline file.pg` | Symbols with content hashes, as JSON |
| `pygo edit file.pg --replace KEY [--expect-hash H]` | Replace/insert/delete by symbol key |
| `pygo explain [--json] CODE` | Wrong/right example for a diagnostic or runtime code |
| `pygo compile -o app.pgc file.pg` | Compile to bytecode (faster start) |
| `pygo disasm file.pg` | Show the generated bytecode |
| `pygo build -o app file.pg` | Self-contained executable |
| `pygo extern python MODULE NAME...` | Draft a typed Python binding — never write one by hand |

Exit codes: `0` ok · `1` unhandled failure in `main` · `2` panic · `3` compile
error · `4` capability not granted.

## The language on one screen

```
import "json"

/// A user. `let` is the only module-level binding (no global mutable state).
struct User { name: Str, age: Int = 0, email: Str? }

fn adult(u: User) -> Bool => u.age >= 18          // expression body

fn parse(text: Str) -> !User {                    // !User = may fail
    return try json.decode_as(text, schema: User)
}

fn main() -> ! {
    let u = try parse("{\"name\": \"ada\", \"age\": 36}")
    match u.email {                               // match must be exhaustive
        nil  => print("${u.name}: no email"),
        addr => print("${u.name} <${addr}>"),
    }
    print(json.encode({"adult": adult(u)}))
}
```

- Types: `Int`, `Float`, `Str`, `Bool`, `Html`, `List[T]`, `Map[K, V]`,
  `T?` (optional), `struct`, `enum`, `fn(A) -> B`, generics `fn id[T](x: T) -> T`.
- Errors: `fail("E_CUSTOM", "msg")`, `panic("bug")`; handle with `try`/`catch`.
- Lists/maps are thread-safe; `spawn f(x)` returns a `Task[T]` (`try t.wait()`).
- Strings: `"${expr}"` interpolation, `.split`, `.map`, `.filter`, `.join`, ...
- `import "json"` for stdlib, `import "./lib/geo"` for a local `geo.pg`.

## Safety: effects are capabilities

The closed set is `clock crypto env fs net proc python rand sql`. A function that
performs an effect — or calls one, or holds one as a value — must declare it
(`E0501`); declaring an unused effect warns (`W0503`).

```
fn load(path: Str) -> !Str uses fs { return try fs.read(path) }   // declares fs
```

- Default is **deny all**: without `--allow`, a program can only compute and print.
- Grant exactly what is needed: `pygo run --allow fs,net app.pg`.
- A missing grant fails fast with `main declares capabilities that were not
  granted` (exit 4); a runtime misuse is `R0010`.
- Free (no grant): `print`, `eprint`, `log.*`, `time.sleep`, `read_line`,
  `os.args`, and the pure crypto/JWT functions below.

## Crypto and JWT

```
import "crypto"
import "jwt"

let digest = crypto.sha256("abc")                       // lowercase hex
let mac    = crypto.hmac_sha256("key", data: "message") // second arg by name
let safe   = crypto.equal(mac, b: expected)             // constant time
// PBKDF2-HMAC-SHA256: ~10k+ iterations, 32-byte key
let hash   = try crypto.pbkdf2(password, salt: salt, iterations: 100000, length: 32)

let token  = try jwt.sign_hs256({"sub": "ada"}, key: secret)   // HS256
let claims = try jwt.verify_hs256(token, key: secret)          // !Map[Str, Any]
```

Only `crypto.random_bytes(n)` is an effect (`uses crypto`); it draws from the
seeded generator, so replays are reproducible. `verify_hs256` checks the
signature and `alg`; compare `exp`/`nbf` yourself (it stays pure).

## HTTP services

Handlers are `fn(Request) -> Response`; `dispatch` matches routes and applies
middleware left-to-right. Build HTML only with `html"..."` (every `${}` is
escaped for where it appears), so injected markup is impossible.

```
import "http"

fn show(req: http.Request) -> http.Response => http.json(200, body: {"id": req.params["id"]})

fn routes() -> List[http.Route] {
    return [http.Route{method: "GET", path: "/items/{id}", handler: show}]
}

fn main() -> ! uses net {
    try http.serve(":8080", handler: fn(req) => http.dispatch(
        req, routes: routes(),
        middleware: [http.request_id(), http.log_requests(), http.recover()],
    ))
}
```

- 405 when only the method differs, 404 otherwise; same path wins in order.
- Bodies over `max_body` (default 1 MiB) get 413 before the handler runs.
- TLS: pass `tls: http.Tls{cert: "cert.pem", key: "key.pem"}` to `serve` for HTTPS (TLS 1.2+). The pair is reloaded from disk when it changes (no restart); a broken renewal keeps the last good certificate. A bad path is an `E_TLS` failure before the port opens. A reverse proxy is equally fine.
- Test a handler directly with an `http.Request{...}` literal — no socket needed.
- Observability: add `http.metrics()` to the middleware and serve `http.metrics_text()` at `/metrics`; `/healthz` and `/readyz` are plain routes. `http.tracing("service", endpoint: "http://host:4318")` exports OTLP/HTTP spans (`uses net`).

## PostgreSQL (`sql`)

A PostgreSQL client lives in the runtime (no driver, no CGO); it needs the
`sql` capability. The socket opens lazily on the first statement, so `open`
fails only on a bad connection string.

```
import "sql"

struct Item { id: Int, name: Str, price: Float }

fn list(conn: sql.Conn) -> !List[Item] uses sql {
    return try sql.query_as(conn, text: sql"SELECT id, name, price FROM items ORDER BY id", schema: Item)
}

fn add(conn: sql.Conn, name: Str, price: Float) -> !Int uses sql {
    let rows = try sql.query(conn, text: sql"INSERT INTO items (name, price) VALUES ($1, $2) RETURNING id", args: [name, price])
    return int(rows[0]["id"])
}
```

- `sql.query(conn, text: sql"...", args: [...])` → `List[Map[Str, Any]]`; `query_as(..., schema: T)` decodes rows into `T` (`E_SCHEMA` on mismatch); `exec` → affected rows.
- Parameters are sent out of band with the extended query protocol: use `$1, $2, ...` (a `?` is rewritten to `$n` when args are passed). Never build SQL with `${}` (E0121).
- `open` takes a URL (`postgres://user:pw@host:5432/db?sslmode=disable`) or `key=value` pairs; auth is SCRAM-SHA-256/MD5/cleartext. Errors are `E_SQL` (with the SQLSTATE).

## Determinism and budgets

Same source + same inputs + same seed `=>` same output, on every engine.

- `--seed N` seeds `rand` and `crypto.random_bytes`; map iteration order is insertion order.
- `clock` (wall time) exists only behind the `clock` effect; integer overflow is an error, not a wrap.
- `--max-steps N` and `--timeout 30s` bound a run; `--json` reports the result on stderr.

## Tests

```
test "items round-trip" {
    let u = try parse("{\"name\": \"ada\", \"age\": 36}")
    assert adult(u)
    assert u.name == "ada"
}
```

`pygo test --json dir` runs every `test`. Each program also runs on the tree
interpreter, the bytecode VM, and the VM from a compiled `.pgc`, which must
agree on output, errors and step count.

## Editing code as an agent

```
pygo outline lib/geo.pg                     # keys + hashes (JSON)
pygo edit lib/geo.pg --replace fn:area \
     --expect-hash 3f9c... --code 'fn area(r: Float) -> Float => 3.14159 * r * r'
pygo fmt -w lib/geo.pg && pygo check --json lib/geo.pg
```

`--expect-hash` makes the edit atomic: it refuses if the symbol changed.

## Do / Don't

- Do run `check` and `test` after every edit; read the `code`, `hint` and `fix`.
- Do return `!T` for anything that can fail, and handle it.
- Do keep effects minimal and explicit.
- Don't invent stdlib names or Python bindings — `describe` and `extern python` exist for that.
- Don't use `python` for crypto, JSON, HTTP, SQL or regex; the stdlib covers them without a sandbox.
- Don't edit by line offset; use `outline` + `edit`.
